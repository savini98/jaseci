- **Feature: GraphMend -- source-level elimination of PyTorch 2 FX graph breaks (`--graphmend`)**: An opt-in compiler phase that rewrites the Python lowering target so TorchDynamo can capture larger, uninterrupted FX graphs, with no change to model code. Three transformations run before `PyastGenPass`, each gated by a conservative legality analysis over the unified AST/CFG/symbol-table IR, and each declining rather than rewriting when safety cannot be established: `[Where]` predicates two-way data-dependent branches into a single `torch.where` (or `torch.cond` where a branch value contains a call, so only the taken path runs); `[Defer]` buffers `print`/logger calls and replays them in FIFO order after the compiled region, on normal *and* exceptional exits; and `[Trap]` lowers `if not C: raise E(msg)` validation guards to the graph-native `torch._assert_async`, restoring the original exception type at the eager boundary. Hoisting an existence-guarded initializer out of a branch is licensed only when the memoized attribute is confined to the rewritten region and the initializer resolves to code proven pure and non-raising for its arguments, so speculation cannot create observable state or exceptions the original program avoided. `--graphmend-scope <prefixes>` extends the rewrite to imported `.py` model code, including Hugging Face `trust_remote_code` modules, which are reached by hooking the source loader in addition to `sys.meta_path`; `torch` and `jaclang` are never intercepted. GraphMend output is cached in its own variant-keyed slot so transformed and untransformed bytecode can never be served to the wrong run. Verified on real Hugging Face models: Phi-4-mini (5 breaks to 0, the LongRoPE branch), MoLFormer-XL (5 to 0, `torch.equal` attention-mask guard), and four logger-break models, all with bit-identical FP32 output.
